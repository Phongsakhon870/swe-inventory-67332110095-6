# รายงานการตรวจสอบการเข้าถึงและการใช้งาน (Accessibility & Usability Review)

เอกสารบันทึกการประเมินการออกแบบ UI Mockup ตามเกณฑ์มาตรฐาน **Web Content Accessibility Guidelines (WCAG 2.1 ระดับ AA)** สำหรับระบบจัดการสินค้าคงคลัง (Lab 04)

---

## 1. ตารางตรวจสอบ Accessibility Checklist

| รายการตรวจ | ผ่าน หรือ ไม่ผ่าน | สิ่งที่ตรวจพบและสิ่งที่ปรับปรุงแก้ไข |
|---|---|---|
| **1. ข้อความหลักสี `#111827` บนพื้นขาว มี contrast อย่างน้อย 4.5 ต่อ 1** | **ผ่าน** ✅ | สีตัวอักษร `#111827` บนพื้นหลังสีขาว (`#FFFFFF`) มี Contrast Ratio สูงถึง **16.1:1** ซึ่งผ่านเกณฑ์ WCAG Level AAA (> 7:1) ทำให้อ่านง่าย ชัดเจน ไม่ปวดตา |
| **2. ปุ่ม Primary มี contrast เพียงพอ** | **ผ่าน** ✅ | ปุ่ม Primary ใช้สีพื้นหลัง `#1E40AF` พร้อมข้อความสีขาว (`#FFFFFF`) มี Contrast Ratio อยู่ที่ **8.6:1** (ผ่านเกณฑ์ 4.5:1 สำหรับ Normal Text และ 3:1 สำหรับ UI Components) |
| **3. ทุกช่องกรอกมี label ที่มองเห็น** | **ผ่าน** ✅ | ปรับแก้จากแบบร่างเดิมของ AI ที่ใช้แค่ Placeholder โดยเพิ่ม `<label>` ถาวรค้างไว้เหนือช่องกรอกทุกช่อง ทำให้ผู้ใช้ไม่ลืมความหมายของช่องเมื่อเริ่มพิมพ์ |
| **4. ช่องที่บังคับกรอกมีสัญลักษณ์ชัดเจน** | **ผ่าน** ✅ | เพิ่มเครื่องหมายดอกจันสีแดง `*` และกำกับข้อความระบุชัดเจนว่า "(เครื่องหมาย * หมายถึงช่องที่จำเป็นต้องกรอกข้อมูล)" เพื่อให้ผู้ใช้ระดับ 2 สังเกตเห็นได้ทันที |
| **5. error ไม่ได้ใช้สีอย่างเดียว มีไอคอนและข้อความด้วย** | **ผ่าน** ✅ | ทุกสถานะแจ้งเตือนข้อผิดพลาด (Validation Error) ประกอบด้วย: (1) ไอคอนเครื่องหมายตกใจ `⚠️` หรือ `[!]`, (2) กรอบสีที่มี Contrast ชัดเจน, และ (3) ข้อความอธิบายวิธีแก้ไข |
| **6. ลำดับการกด Tab เรียงบนลงล่าง ซ้ายไปขวา** | **ผ่าน** ✅ | จัดเรียง DOM / Tab Order ตามลำดับ Logical Reading Order จากซ้ายไปขวา และบนลงล่าง: ประเภทสินค้า -> รหัส -> ชื่อ -> หมวดหมู่ -> ราคา -> จำนวน -> ปุ่มยกเลิก -> ปุ่มบันทึก |
| **7. ปุ่มมีชื่อบอกหน้าที่ชัด ไม่ใช่ OK หรือกากบาท** | **ผ่าน** ✅ | ไม่ใช้คำคลุมเครือ เปลี่ยนเป็นชื่อระบุการกระทำชัดเจน เช่น "💾 บันทึกข้อมูลสินค้า *" และ "ยกเลิก (Cancel)" ช่วยลดความผิดพลาดในการกดปุ่ม |

## 2. จุดบกพร่องที่ AI ทำพลาดและนักศึกษาเป็นผู้ตรวจพบและแก้ไขเอง (อย่างน้อย 2 จุด)

### 🔴 จุดที่ 1: AI ใช้ Placeholder แทน Label ถาวร (Vanishing Label Issue)
- **สิ่งที่ AI สร้างมาให้:** AI สร้างฟอร์มที่มีเพียง `<input placeholder="กรอกชื่อสินค้า">` โดยไม่มีแท็ก `<label>` อยู่ภายนอก
- **ปัญหาทาง Usability & Accessibility:** เมื่อพนักงานเริ่มพิมพ์ตัวอักษรตัวแรก ข้อความ placeholder จะหายไปทันที ทำให้พนักงานคลัง (Persona: สมชาย ทักษะ 2/5) เกิดความสับสน ลืมว่าช่องนี้คือชื่อสินค้าหรือรหัสสินค้า และ Screen Reader สำหรับผู้พิการทางสายตาจะไม่สามารถอ่านชื่อฟิลด์ได้อย่างถูกต้อง
- **สิ่งที่นักศึกษาแก้ไข:** เพิ่ม Persistent Label ที่มองเห็นได้ตลอดเวลาไว้เหนือทุกช่องกรอก และคง placeholder เป็นเพียงตัวอย่างรูปแบบข้อมูล (Example Hint)

### 🔴 จุดที่ 2: การใช้สีเพียงอย่างเดียวในการสื่อความหมายสถานะสต็อกต่ำ (Color Alone for Status)
- **สิ่งที่ AI สร้างมาให้:** AI ในร่างแรกแนะนำให้เปลี่ยนแถวในตารางเป็นสีส้ม/แดงเมื่อสต็อกต่ำ โดยไม่มีไอคอนหรือข้อความบอกสถานะเพิ่มเติม
- **ปัญหาทาง Accessibility (WCAG 1.4.1 Use of Color):** ผู้ใช้ที่มีภาวะตาบอดสี (Color Blindness เช่น Red-Green blindness) จะไม่สามารถแยกแยะได้ว่าแถวไหนเป็นสินค้าปกติและแถวไหนเป็นสต็อกต่ำ
- **สิ่งที่นักศึกษาแก้ไข:** ปรับแก้ตารางใน Dashboard โดยเพิ่มคอลัมน์ "สถานะ" ที่มีไอคอนเตือน `⚠️` และข้อความระบุชัดเจนว่า "ต่ำกว่าเกณฑ์" ควบคู่ไปกับสีเตือน `#B45309` และแสดงปุ่มลัด `[สั่งซื้อเติม]` ทันที

### 🔴 จุดที่ 3: ข้อความ Error แจ้งเตือนแบบคลุมเครือ ไม่บอกวิธีแก้ไข
- **สิ่งที่ AI สร้างมาให้:** ในช่องราคา AI ใส่ข้อความแจ้งเตือนว่า *"Invalid input"* เมื่อผู้ใช้กรอกผิด
- **ปัญหาทาง Usability:** ผู้ใช้ไม่รู้ว่าผิดเพราะอะไร กรอกติดลบ ผิดรูปแบบ หรือไม่ใส่ทศนิยม
- **สิ่งที่นักศึกษาแก้ไข:** เปลี่ยนข้อความ Error ให้มีความหมายและบอกทางออก (Constructive Guidance) เช่น *"⚠️ ราคาต่อหน่วยต้องเป็นตัวเลขที่มากกว่า 0 บาท"*
